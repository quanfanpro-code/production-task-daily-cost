# 随附工具的参数与格式

本页是维护用的详细格式手册。正常提取和交付所需调用及简短结构已在SKILL.md中给出，遇到实际接口问题再查本页。使用本机已核实的Python，缺依赖再安装。

## 可选命令

- 本地准备：`scripts/预处理拆分.py prepare --source 原件PDF或目录 --output 工作目录`，返回提取视图路径，内有页图、原页、识别文字和问题。旧成果直接接续，保留原始缓存。
- 专业识别：同一执行者运行`scripts/智谱文字识别.py --index 准备索引.json --output 识别目录 --cache 共用缓存目录`，程序从本地缓存裁图并读取专业缓存，不重做本地OCR；已有提取视图时用`--pages 提取视图.json`代替`--index`。默认顺序执行，无业务提示词；图片内容、模型和参数相同直接复用。原始服务响应包含表格、布局和用量，成功及失败均保留；失败默认不重复请求，诊断后才用`--retry-failed`。密钥从ZHIPU_API_KEY或仓库外Windows用户加密文件读取，不保存在仓库。
- 已有核定任务生成表格：`scripts/生成交付.py --input 核定任务.json --output 交付目录`，返回已检查的任务数、行数和特殊情况。
- 需要单独拆分PDF时：`scripts/预处理拆分.py split --plan 拆分方案.json --output 拆分目录`。准备索引的files可直接用于下述方案。

程序用本机解释器执行，路径参数传完整路径。智能助手负责理解格式、起止/时点含义及模糊日期，程序不从raw关键词重判kind，也不按编号和相邻日期改写已采用年月。专业识别结果的text保留文字和表格，layout保留专业模型返回的块类型和位置，专业表格保留行列结构。本地粗识别只用于方向、页面分类、图纸过滤和裁剪定位，不能用它识别出的日期、属性或工序补字段；不向提取阶段传递coarse_rows或本地全文。完整原始响应保存在cache_file对应文件。已有裁图直接使用；每页成功响应分别缓存，整批结束只写一次汇总。智能助手整理必要字段和原日期，固定程序推算和写表。

准备索引的image保留原页，cost_region保留裁剪坐标、局部路径和输入面积；提取视图只提供局部图片和来源定位，不输出本地具体读数。每页仅竖切一刀，从左边保留至最右必要字段，整页高度和内部位置不变，一页一图；没有逐列拆图、拼接或缩放。图纸退出视图。计划、旧式竖版记录为定位字段所需的下半部自动补读一次；后续复用。定位失败通过region_problem明确标示，保留原页，不冒称已裁剪。


## 拆分方案

顶层 `source_root` 是原件目录，`files` 从准备索引拷贝，按相对文件名映射页数 pages 与 sha256。`segments` 每个分段包含 source_file、start、end、task_no、action，可加 id、reason、rotations。

start/end都是从1计数的原件页码且含末页。错位附件可在同一个保留段指定 page_numbers，例如[1,3]；它必须是起止范围内升序且不重复的页列表，输出页序按此列表，未指定时采用完整区间。仅允许同一source_file选页，不跨副本拼接。action只有 keep（保留任务）、duplicate（重复件）、unassigned（未知保留）。duplicate必须提供 duplicate_of 指向同任务keep段的id，且提供reason。每页恰好一个去向。不允许同任务keep多份、不允许越界、漏页或重叠。

rotations是字符串原件页码映射至顺时针纠正角度0/90/180/270，是相对原PDF显示方向再加的纠正角度。从准备索引复用，方向不确定须先看图核定。未提供视为不追加转角。编号保留原字符，文件名中的Windows禁用字符才替换；发生文件名碰撞必须先解决身份。

## 核定任务

顶层是 tasks 数组。每项有 task_no、product_name、spec、material、material_date、incoming_dates、delivery_date、batch_date、plan、records、warnings。日期写成完整年-月-日；空缺用null，禁止把解释塞进日期字段。编号字符串非空且唯一。

plan是列表：每项 process、start、end、source、raw。有明确计划内容但无日期可留空，由规则兜底；纯空白行、斜线和“视情况”不是已经安排发生的依据，不建立计划项。检验计划区间取end当天。

records每项包含：

| 字段 | 含义 |
| --- | --- |
| process | 核定大工序，不是每个加工面 |
| kind | point完成时点、range明确起止、inspection检验、blank空白 |
| date、end | 按所在表格列头确定kind，原表两日期列都保留；point的end也是完成时点；range的end才是结束日；检验只填当天 |
| source | file原文件、page原页、location行位置；可补拆分页与原件散列 |
| raw | 工序日期相关原文字样或已有提取对象，不能改写成推算结果；整页原文另用原页和已有缓存保留，无需模型重抄无关内容 |
| estimated、reason | 原件字迹是否估读及其依据；检验有原日期就填date，缺日期留null让程序补，不能用estimated把两者混为一谈；计划来源由脚本标示 |
| candidates | 可选排他候选，每项value是日期，beats列出已用证据击败的候选值；比较依据写reason |

start可选，只用于已经核定的特殊起点，为含date、basis的对象。默认不填，避免覆盖常规优先级。所有任务无论是否空白均进入tasks；产品规格材料无法确认可留空，别把“辨读不清”等句子放主表。

脚本处理日期规则和表格，不辨认原图。连编号、计划和相关日期都没有时，依据批次命名或用户提供期间确定batch_date，标明低把握估算。

## 输出与保护

表内开始、结束日期照对应列头处理；表外加工或返修另记point，明确写了起止的才记range，不增加repair或reviewed标记。纯交接及作废等非加工事实可保留在任务notes中，不当成加工日期。生成器保留六列、日期、去重、互斥分流和文件结构的基本检查，直接返回结果，不另写交付验证或数据说明。原始提取每任务保存一次，推算理由按采用的日期范围保存。明显日期冲突先用已有信息判断，仅有必要时补读对应局部，仍不清合理估算，不全量复核。原件不写回，覆盖已有文件前自动备份并核对散列。

准备索引中的file_errors记录文件问题，pages中的problem和direction_uncertain记录页面问题。原件与缓存保留，识别失败不当作空白。

## 同一工作目录复用与补读

prepare先识别顶部45%，为定位字段对计划和旧式竖版记录自动补读下部；新扫描件使用默认参数，已有可用成果时可用`--no-ocr`。其他确需更多文字的页，先排除图纸及已完成内容，把待补有效页集中到同一清单，在原工作目录用`--ocr-scope full --page-list 原页清单.json`一次补读，仅补未覆盖的下部55%。清单是由`source_file`、`page`组成的数组，文件名对应原件相对名，页码从1计数。未列出的页不发起新的识别；不从拆分副本另起prepare。缺失或越界页会报错，不作为已完成。

每页索引保留`page_cache_key`、`ocr_coverage`（none/header/full）、`text_source`及`ocr_regions`。区域状态ok表示实际执行成功，包括无文字返回；failed表示失败，不能当空白。上部与下部框坐标均对应同一转正图，不对下部框再次加偏移。已有文字层可用时覆盖整页，不额外请求识别。旧版顶部缓存兼容复用；旧`--no-ocr`页图也可复用。缺图只重建图片。

默认再次运行不重试失败区域；先诊断，必要时加`--retry-failed`只补失败区域，成功部分保留。同一页参数不变无需重新识别；新服务/模型/参数试验另存参数和结果身份，成功缓存不能被失败覆盖。输入有变化按新散列核对，不能继续沿用旧归属。
