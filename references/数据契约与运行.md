# 数据契约与运行

本页给执行agent使用，用户不需要抄命令。路径参数使用完整Windows路径。优先按宿主已核实的原生Python路径运行，不用WorkBuddy自带运行时；解释器完整路径由执行环境确认，其他Windows电脑使用其已核实的本机解释器。首次检查 requirements.txt 所列依赖，缺少才安装，不反复重装。

## 运行顺序

以下参数中的目录由agent替换为用户授权路径，不能照抄示例。需要选择时使用系统文件夹选择窗口。

1. `预处理拆分.py prepare --source 原始目录 --output 工作目录`。抽样可加 `--limit-pages 6`，正式全批不加；来源目录混有旧拆分或转正副本时，用可重复的 `--exclude 子目录名` 明确排除，并将排除清单与盘点核对；`--no-ocr`仅用于已有可用文字层或人工检查，不意味着已完成精提取。
2. 读取准备索引、页面图和原PDF。完成归属后写拆分方案。
3. `预处理拆分.py split --plan 拆分方案.json --output 拆分目录`。
4. agent读取拆分后的图像、记录原文与日期角色，写核定任务.json。
5. `生成交付.py --input 核定任务.json --output 交付目录`。
6. 阅读初算异常清单并核对原图，更新中间数据、重新生成；自动备份已有交付。回读交付验证与特殊情况汇报。

`导入历史.py --source 旧JSON目录 --output 迁移任务.json --batch-date 2026-07-01` 仅供历史规则回归。它按旧字段推定日期角色，需明确其局限。不能把参数日期固定用在其他批次。

## 拆分方案

顶层 `source_root` 是原件目录，`files` 从准备索引拷贝，按相对文件名映射页数 pages 与 sha256。`segments` 每个分段包含 source_file、start、end、task_no、action，可加 id、reason、rotations。

start/end都是从1计数的原件页码且含末页。错位附件可在同一个保留段指定 page_numbers，例如[1,3]；它必须是起止范围内升序且不重复的页列表，输出页序按此列表，未指定时采用完整区间。仅允许同一source_file选页，不跨副本拼接。action只有 keep（保留任务）、duplicate（重复件）、unassigned（未知保留）。duplicate必须提供 duplicate_of 指向同任务keep段的id，且提供reason。每页恰好一个去向。不允许同任务keep多份、不允许越界、漏页或重叠。

rotations是字符串原件页码映射至顺时针纠正角度0/90/180/270，是相对原PDF显示方向再加的纠正角度。从准备索引复用，方向不确定须先看图核定。未提供视为不追加转角。编号保留原字符，文件名中的Windows禁用字符才替换；发生文件名碰撞必须先解决身份。

## 核定任务

顶层是 tasks 数组。每项有 task_no、product_name、spec、material、material_date、incoming_dates、delivery_date、batch_date、plan、records、warnings。日期写成完整年-月-日；空缺用null，禁止把解释塞进日期字段。编号字符串非空且唯一。

plan是列表：每项 process、start、end、source、raw。有明确计划内容但无日期可留空，由规则兜底；纯空白行、斜线和“视情况”不是已经安排发生的依据，不建立计划项。检验计划区间取end当天。

records每项包含：

| 字段 | 含义 |
| --- | --- |
| process | 核定大工序，不是每个加工面；备注可用原栏目名 |
| kind | point完成时点、range明确起止、inspection检验、note备注、blank空白 |
| date、end | 时点只填date；range分别填开始和完成；检验只填当天 |
| source | file原文件、page原页、location行位置；可补拆分页与原件散列 |
| raw | 完整原文或原始提取对象，不能改写成推算结果 |
| estimated、reason | 必要日期是否推定，以及依据；计划来源另由脚本标示 |
| candidates | 可选排他候选，每项value是日期，beats列出已用证据击败的候选值；比较依据写reason |

start可选，只用于已经核定的特殊起点，为含date、basis的对象。默认不填，避免覆盖常规优先级。所有任务无论是否空白均进入tasks；产品规格材料无法确认可留空，别把“辨读不清”等句子放主表。

agent应在调用生成前解决工序归属和来源定位。脚本只做明确规则，不具备看原图的能力。结构报错应由agent回到证据修正，不把中间格式问题甩给用户。连编号、计划和相关日期都没有时，依据批次命名或用户提供期间确定batch_date，标明低把握估算。

## 文件与验证

示例 `examples/合成任务.json` 不含真实生产资料。`assets/六列交付模板.xlsx` 是空白格式示意，无需手填。`tests/测试全流程.py` 运行规则和文件保护的验收；退出码0才算通过。

脚本覆盖文件前自动复制到用户 BackUp 目录并核对散列，相同内容不覆盖。PDF原件不写回。输出目录不能包含原件目录，允许是原件内独立子目录，准备阶段会排除该输出子目录。实际输入应明确排除已有拆分和历史输出，避免同一批资料重复收进来。

交付前阅读完整计算结果的tasks和warnings，核对留痕全覆盖；核对异常任务跨度与原图复核结论一致。自动回读检验只是结构验证，不代表全部手写内容正确。

准备索引的file_errors记录无法打开或加密文件；pages中的problem记录渲染/识别问题，direction_uncertain记录方向不确定。agent先用其他可用阅读方式恢复，不能恢复的原件保留并列入汇报，其余可读文件继续。坏缓存自动备份重建，图片缺失重新生成。

## 同一工作目录复用与补读

prepare默认只识别顶部45%，`--no-ocr`跳过识别但与后续识别共用页图。核定有效页后，在同一原件目录与工作目录再次prepare，使用`--ocr-scope full --page-list 原页清单.json`，只补未覆盖的下部55%。清单是由`source_file`、`page`组成的数组，文件名对应原件相对名，页码从1计数。未列出的页不发起新的识别；不从拆分副本另起prepare。缺失或越界页会报错，不作为已完成。

每页索引保留`page_cache_key`、`ocr_coverage`（none/header/full）、`text_source`及`ocr_regions`。区域状态ok表示实际执行成功，包括无文字返回；failed表示失败，不能当空白。上部与下部框坐标均对应同一转正图，不对下部框再次加偏移。已有文字层可用时覆盖整页，不额外请求识别。旧版顶部缓存兼容复用；旧`--no-ocr`页图也可复用。缺图只重建图片。

默认再次运行不重试失败区域；先诊断，必要时加`--retry-failed`只补失败区域，成功部分保留。同一页参数不变无需重新识别；新服务/模型/参数试验另存参数和结果身份，成功缓存不能被失败覆盖。输入有变化按新散列核对，不能继续沿用旧归属。

## 试跑与小批交接

先完成代表页的读图、写出JSON和主agent来源核对，再批量。`服务试跑.json`至少记录：本地识别/宿主读图/可选在线识别的通道区分、实际环境与模型（宿主不公开则如实记不可见）、已知请求参数、图片尺寸、超时/耗时、输入原页及散列、输出路径、校验结论。不得记录令牌或密码，不得编造宿主隐藏参数。新增在线渠道需独立跑通，不能把本地OCR通过写成在线通过。

每个任务包包含批次标识、允许原页列表与固定标签、任务编号范围、原文件散列和输出路径。子代理结果保存原文/记录及逐页回执，回执列明原标签、原文件、原页与实际处理状态。主agent用本地脚本读取准备索引和任务包，逐条核对来源存在、在分配集合、标签与编号匹配、无重复或漏页，再合并tasks。拆分页须先通过拆分清单还原原页，不能凭联络表格子序号猜原页；回执或文件缺失的页保留为未完成。

常态至多2个在途请求，错误后降为1个，子代理不得再并发。执行者记录发出、成功落盘、验收通过或失败，成功批次断点续用。先回收或确认旧调用结束再重派；不知道是否结束时仍计入在途。按SKILL.md的等待和补试上限处理，仅重做失败范围。这里是宿主执行约束，prepare本身串行且不提供网络调度器。
