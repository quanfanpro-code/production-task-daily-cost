# 📋 生产任务扫描件，整理成每天一行的成本明细

这个技能帮助你把一堆扫描的生产任务单，整理成可以直接筛选、统计、做数据透视的 Excel 表格。

你提供原始文件夹或单个扫描文件，告诉智能助手按这个技能处理。助手负责辨认页面、分任务、核对重复件、读取记录、补齐缺少的日期，再生成表格和说明。你不需要自己抄单据，也不需要学习编程。

它适合这样的资料：一份生产任务有一张带编号的生产计划，后面夹着图纸或工艺规范、工序记录，有时还有来料检验和成品检验。手写不清、日期缺失、同一任务重复扫描，都属于它要处理的日常情况。

## 🎯 你最后会拿到什么

最主要的文件是“生产任务_成本逐日明细.xlsx”，里面有三张工作表。

| 工作表 | 放什么 | 你怎么用 |
| --- | --- | --- |
| 逐日明细 | 一般工期任务，每个工序每天一行 | 平时统计、按月归集成本 |
| 异常工期逐日明细 | 达到183天的任务，完整保留每天记录 | 单独检查，决定是否合并参与成本计算 |
| 留痕 | 原件文字、来源页、补日期的理由、异常说明 | 有疑问时查“这行是怎么来的” |

前两张表都只有六列，顺序固定：**任务编号、产品名称、规格、材料、工序、日期**。

例如，某任务的精磨从1月1日持续到1月10日，表里就有十行：1月1日一行、1月2日一行，一直到1月10日。每一行工序都写“精磨”。不需要再加“天数=1”，也不在每一行重复开始日和完成日。

如果1月10日同一个任务既精磨又双轴，当天可以有两行。它们属于不同车间，分别计入。同一个任务同一天重复写了两次精磨，则合并为一行，两个原始记录都留在留痕里。

除工作簿外，还会生成“特殊情况汇报.md”和“数据说明.md”。前者列出本次出现的长工期、补日期、空白任务和其他问题；后者解释怎么使用结果。拆分清单记录每一页去了哪里。完整计算结果和交付验证由助手保存，方便后续复查、重跑，你日常只看工作簿和中文说明即可。

## 🚀 第一次怎么用

1. 准备一台 Windows 电脑，以及能读取本机文件、查看图片、运行本地程序的智能助手。WorkBuddy、Codex 等都可以作为执行入口，前提是你给它相应的文件访问能力。
2. 将完整的 production-task-daily-cost 文件夹放进你统一管理技能的目录。不要只复制一个说明文件：里面还带有方向模型、表格模板和处理程序。
3. 告诉助手：“请加载这个文件夹里的 SKILL.md，按它处理我的生产任务扫描件。”如果软件已有“安装本地技能”的入口，也可以通过那个入口选择整个文件夹。不同软件入口名称可能不同，助手可以自行检查。
4. 把原始扫描件放在一个独立文件夹，尽量只放这一批的原件。不要把原件、旧拆分结果和旧交付表混在一起。已经混放也不用你手工整理，告诉助手哪些是原件即可。
5. 让助手打开系统文件夹选择窗口，选择原件目录和结果目录。你也可以直接把已经知道的完整目录发给助手。
6. 给助手一句明确指令：“按照生产任务逐日成本技能处理这个目录，缺失日期按规则补齐，输出六列逐日明细、183天异常页、留痕和特殊情况汇报。”随后由助手执行。

第一次运行时，助手会检查本机 Python 和必要组件。已安装的直接使用；确实缺少才安装。你无需自己找一串命令，也不需要为每个任务安装一次。

本项目供智能助手使用。程序负责本地准备、日期推算和表格生成；助手先使用已有文字和字段，只补看不清或缺失的日期。不是每一页都重新交给大模型看图。

## 🔄 下一批怎么用

把新批次原件放在新的文件夹，让助手继续使用同一个技能，并指定新的结果目录。它会沿用六列、日期补齐、检验一天和183天异常规则，不会沿用上一批的任务编号、年份、任务数和路径。

如果中途被打断，告诉助手“从已有工作目录继续”。页面、文字识别和已经核定的字段都会继续使用。已有完整任务数据时直接生成交付，不重新走识别流程。只修改日期规则或重新生成表格，不需要重新识别。原文件内容改变时，受影响原件会使用新的内容指纹核对；文件级指纹变化可能涉及该文件全部页。最终表格更新前会备份旧文件。

如果你决定调整规则，例如异常工期改成另一标准，应明确告诉助手修改规则并重新生成。不要直接改其中几行后又让旧规则覆盖，否则难以区分哪些是你手工改过的。

## 🧭 它实际怎样处理

### 1. 先数清资料

先登记原文件、页数和文件内容指纹。内容指纹可以理解为文件的“身份证”，用来确认过程中是否拿错文件、是否被改过。原件始终保留。

### 2. 把页面转正，顺便找任务首页

横着、倒着的页面先判断方向。本地小模型负责转正，本地文字识别粗读页头，寻找计划、工序记录、检验以及图纸规范。已有文字和页图直接复用；没有可用识别的新扫描件不能跳过必要的本地准备。

看不准方向时，助手直接看图判断。编号虽然属于前期工作，也必须认真核对，因为编号一错，后面的拆分、去重和成本归属都会错。

### 3. 拆成一份一份任务，再处理重复件

从某张任务计划首页开始，到下一张任务首页之前，形成一个候选任务。助手再核对产品、规格、编号和附件，确认这些页确实属于同一任务。

重复扫描的同一任务，选内容最完整的一份作为采用来源，记录采用理由。图纸和技术规范跟着任务保留，但提前退出后续全文识别和大模型提取。页面通常按计划、图纸规范、工序记录排列，助手结合页头与顺序判断，不能只留第一页和最后一页。多页记录及中间的检验单仍需保留。无法归属的页不丢弃，错位附件按实际归属处理。

### 4. 只读需要的字段

工序记录只取工序、日期和对应列头；尺寸、面形、光洁度、签名等不逐项抄写。成品检验只取检验日期。生产计划只补任务编号、产品名称、规格、材料、领料或下料起点，以及缺实际日期时需要的计划日期和预计交付。

已有字段直接用，已有识别文字先用于提取。真正不清楚时，才让模型看相应局部和必要上下文。原始页和已有文字直接保存作留痕，不让模型完整重抄检测表。只有实际估算、冲突和例外才写简短理由。

需要本地补读时把未完成有效页集中处理，已经成功的区域不再识别。换阶段、提示词或输出格式不重新识别。拆分副本不另开一套识别；缺图只补图。

### 5. 用统一规则把日期补齐

实际记录优先。没有实际日期时，计划日期可以补；还有缺失，则结合前后工序、任务编号和交付日期推算一个逻辑合理的值。不会把“看不清”直接变成“待定，让你自己补”。

但完全空白、连计划也没有安排的工序，不凭空编造。这样的任务仍会在留痕和汇报里登记，避免你误以为助手漏处理。

### 6. 展开成每天一行，再检查交付

日期推算完成后，程序自动跨月、跨年展开、去重并分流长工期，执行一次自动内容检查。助手只处理实际异常，不逐行再请模型核验，也不额外做截图、美化或版面验收。

## 🧩 连续处理，避免重复调用

默认由当前助手连续处理完整任务，不要求每一两页重新派人，也不另写试跑证明、逐页回执和正确性说明。已有数据直接接续；已经完成的字段不再交给模型提取。任务完成后只读取汇总和必要异常，整批原文与留痕不反复塞进对话。

单个扫描文件可以直接处理，不需要先复制到新文件夹。准备完成后，助手按任务读取一份精简识别文字，里面已有原页和图片位置；原始坐标保留，需要时才查。生成表格的程序直接返回检查结果、行数和特殊情况，正常完成后不再让模型打开表格重复验收。路径不存在或找不到扫描文件会明确报错，避免“处理了零页却显示成功”。

准备程序运行期间，助手一次等待约半分钟到一分钟接收结果，避免每隔一秒就问一次“好了没有”。这种空查也会反复调用模型，却不会加快识别。

确需分派或在线识别时，同时最多两个任务，服务失败退为一个。已有请求未结束不重复派发；成功部分保留，只补缺口。临时故障按服务要求等待，没有指定时依次等30秒、60秒，最多补试两次。权限或参数错误先修正，不原样重发。

目前没有固定接入专门的在线识别服务。用户批准启用新服务时，先用真实小样跑通，成功结果直接用于本批，不额外制作证明文件；普通裁剪或换批次不重新试跑。

## 📅 几个最容易误会的日期规则

**起点从哪里来？** 优先生产计划上的领料或下料日期；没有才看来料检验；再没有用计划第一道工序的开始日期。之后才依次参考明确实际开始、任务编号日期、相关实际日期、仅有的计划完成日期、仅有的实际检验日期、交付日期和批次参考日期。采用什么依据会写在留痕里。

**只有完成日怎么办？** 将相关加工时点按日期升序排列，按连续加工推算。例如领料6月1日，双轴6月3日、6月8日各有一次完成记录，则前段6月1日至3日，下一段6月4日至8日，合并后这八天都有双轴记录。

**明确写了开始和完成怎么办？** 按记录区间展开。开始和完成都是6月8日，就只算6月8日。不能因为两列日期相同，就当成没有开始日，再向前推十几天。

**两道不同工序同日完成怎么办？** 两道都计当天。如果同日并列而且只有完成点，先前连续段按固定工序顺序分配，留痕说明该推定，不能随着资料读入顺序改变答案。

**成品检验怎么办？** 每个有记录的检验日只算当天。有检验内容没有日期，优先预计交付，再参考最后加工日。推定的检验日不能早于已知最后加工。多次复检分别记各自那一天，不把复检之间每一天都当检验。

**跨半年怎么办？** 从任务采用起点到最后加工完成，包含首尾，达到183天就检查年份、字迹和附件归属。核查后确实这么长，整任务完整放到异常页。没有14天截断，也不在第183天把后面的日期砍掉。

**为什么长工期行数可能没到183行？** 183天看任务起点到最后加工的日历跨度。若原件明确写了多个分散的一天区间，中间没有可连续推算的记录，行数可以小于跨度。反过来，多车间同时加工，也可能行数多于跨度。

## 📊 怎么拿表算成本

按“日期”分组到月份，按“工序”统计行数，就能得到每月各工序的任务天数。按“任务编号”筛选，就能看到这个任务经过哪些工序、每天在哪个工序。

异常表默认与正常表分开。需要纳入时，把两张六列表合并使用；同一任务不会同时出现在两张表中。不要再把异常任务重复加一遍。

这个表提供的是成本分配所需的工序日期基础。每个车间每天的分配金额、材料金额、人工金额以及具体成本分摊政策，由你后续计算。表里没有数量列，因此不要用行数当产量，也不要把各车间行数相加当任务经过的日历天数。

## 🔍 怎么查一条结果有没有依据

在留痕里筛选相同任务编号、工序和日期，可以看到该行属于原件明确区间、实际完成时点、连续推算、计划补齐还是其他估算，并查看源文件、页码、原文和原因。

例如，6月8日有原件完成记录，并不等于6月4日至7日每天都有手写记录。中间日期按连续规则补出，留痕会区分。不能把这些补出来的行数称为识别准确率。

很长的原文会分段保留，不会因为一个格子放不下就悄悄截掉。另有完整计算结果文件保存全部信息，助手可以继续读取。

## 🛠️ 常见情况怎么处理

| 你看到的情况 | 助手应怎么做 |
| --- | --- |
| 日期实在看不清 | 放大、看前后记录和任务年份；仍不清就按统一规则估算，说明理由 |
| 没有任何有效工序记录 | 查计划是否可补；都没有则登记空白，不编造加工 |
| 同任务出现多份 | 核对编号和附件，选择完整来源，保留去重依据 |
| 文件数量和任务数不一样 | 分别解释原文件数、拆分文件数、唯一编号数，不强行凑成同一个数字 |
| 原页和旧图片页码对不上 | 按当前原文件重新核对，不能沿用错位图片的页码 |
| 长工期超过半年 | 先核查；真实或仍按证据合理推定的长工期完整进入异常页 |
| 在线识别或子代理服务失败 | 保留成功结果，停止补派并降到1个；排查后仅补失败部分，不全批原样重试 |
| 运行中断 | 从原工作目录继续，复用页面和识别缓存 |
| 旧表要更新 | 先备份并验证，再重新生成；不要覆盖原始扫描件 |

## 🧪 已做哪些验证，还有什么限制

本项目包含可运行的合成资料验收测试，覆盖跨月、跨年、明确同日起止、同日多工序、缺日期补齐、计划检验、182天与183天边界、重复行、拆分漏页、六列格式、真日期和留痕。

另用一批历史提取资料做过113个唯一任务的迁移回归，并实测了本地页面准备与缓存。迁移回归验证的是旧数据按新规则生成结果，不代表重新辨认了历史全部扫描页。旧表的日期角色混用会影响新旧行数，必须把规则差异和识别差异分开解释。

当前没有完成在线免费识别服务的整批准确率实测，因此不承诺某个免费渠道能识别所有手写字，也不承诺无人参与即可完全正确。助手应完成必要的看图和推断，尽可能交付可用数据，并明确记录仍受原始材料限制的部分。
